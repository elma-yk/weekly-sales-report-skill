# 주간 매출 리포트 (weekly-sales-report)

지난주 월~일 판매내역을 집계해 슬랙 `#주간리포트-테스트`에 올린다. 채널에는 제목 한 줄만 올리고, 리포트 본문은 그 메시지의 스레드에 단다.

## 1. 기간 정하기
- 오늘 날짜는 current_time 도구로 확인한다.
- 리포트 기간은 오늘 이전의 가장 최근 월요일~일요일(지난주)이다.
- 비교 기간(전주)은 그 바로 앞 주의 월요일~일요일이다.
- 제목 형식은 `[주간 매출 리포트] 10/19(월)~10/25(일)`처럼 M/D(요일)로 쓴다.

## 2. 데이터 읽기
- 기준 파일은 구글 시트 **'판매관리의 사본-1'**이다. 드라이브에 '판매관리'(원본, 다른 계정 소유)와 '판매관리의 사본'도 있으니, 파일 선택이 애매하면 사용자에게 확인한다.
- 탭은 `판매내역`이다. 열은 A 주문일, B 주문번호, C 판매채널, D 카테고리, E 상품명, F 옵션, G 수량, H 판매단가, I 결제금액, J 배송비이다. 숫자는 `33,300`처럼 쉼표가 들어 있다.
- 행은 주문일 오름차순이다. 하루에 약 14행이다. 구간 경계는 A열의 몇몇 셀(예: A7300, A7400, A7500)만 읽어 찾고, 두 주가 모두 들어가는 구간을 한 번에 읽는다.
- 시트 전체가 아니라 필요한 구간만 읽는다. 시트 끝까지 데이터가 있는지(마지막 주문일)도 확인해, 대상 주가 모두 채워졌는지 본다.

## 3. 집계 (손으로 계산하지 말고 코드로)
- 읽은 행을 스크래치 파일에 CSV로 옮기고 Python으로 계산한다.
- 날짜별 행 수를 원본 응답과 대조해 옮기다가 빠뜨린 행이 없는지 검증한다.
- 지표 정의는 다음과 같다.
  - **총 매출**: 결제금액 합계. 배송비는 제외한다.
  - **판매 건수**: 시트의 행 개수. 주문번호 중복 제거 건수가 아니다.
  - **판매채널별 매출**: 채널별 결제금액 합계와 비중(소수 첫째 자리 %).
  - **매출 상위 5개 상품**: 상품명별 결제금액 합계 상위 5개. 옵션은 합쳐서 본다.
- 전주 대비 증감은 **총 매출과 판매채널별 매출 옆에만** 붙인다. 정수 %로 쓰고 부호를 붙인다(예: +11%, -3%).

## 4. 사용자에게 먼저 묻기
- 처음 만들 때나 기준이 바뀔 것 같을 때는 기준을 만들기 전에 사용자에게 묻는다(포함 항목, 매출 기준, 전주 비교 여부, 스레드 형식).
- 위 2~3번의 기준은 사용자가 확정한 것이므로 반복 실행 때는 그대로 쓰고, 다시 묻지 않는다.

## 5. 슬랙에 올리기
1. `slack_read_channel`로 채널을 읽어, 같은 제목 줄의 메시지가 이미 있는지 확인한다. **있으면 아무것도 보내지 않고** 사용자에게 알린다.
2. 없으면 제목 한 줄만 채널에 보낸다.
3. 반환된 message_ts를 `thread_ts`로 써서 리포트 본문을 스레드 댓글 1개로 단다.
4. 슬랙 연결에는 메시지 수정 도구가 없다. 보내기 전에 숫자와 형식을 확인한다. 나중에 고쳐야 하면 새 댓글에 '[수정본]'으로 올리고, 기존 댓글은 사용자가 직접 지워야 한다고 알린다.

## 6. 스레드 본문 형식
```
**주요 지표**
• 총 매출: N원 (전주 대비 +x%)
• 판매 건수: N건 (시트 행 기준)

**판매채널별 매출**
| 판매채널 | 매출 (원) | 비중 | 전주 대비 |
(채널별 행 + 합계 행)

**매출 상위 5개 상품**
| 순위 | 상품명 | 매출 (원) |

_전주 매출: 총 N원 (채널별 금액). 결제금액 합계 기준, 배송비 제외._
_출처: 구글 시트 '판매관리의 사본-1' > 판매내역_
```

## 7. 마무리
- 사용자에게는 핵심 수치 몇 줄과 스레드 링크만 짧게 알린다.
- 데이터가 비어 있거나 대상 주가 덜 채워져 있으면 보내지 말고 먼저 알린다.
